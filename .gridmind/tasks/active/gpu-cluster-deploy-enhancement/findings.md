## 发现条目

### 发现 #001

**日期**: 2026-02-25
**阶段**: phase-1
**类型**: 问题
**严重程度**: 中

**标题**: format_disk默认值安全问题

**描述**:
在分析StorageConfig数据模型时，发现`format_disk`字段的默认值为`True`，这可能导致在部署时意外格式化磁盘，造成数据丢失风险。

**影响**:
- 用户可能在不了解情况下丢失磁盘数据
- 与安全最佳实践不符

**解决方案**:
1. 将`src/models/cluster.py`中的`format_disk`默认值改为`False`
2. 将`src/config_loader.py`中的默认值同步修改
3. 更新`src/steps/step_6_disk_mount.py`中的默认值引用
4. 更新配置示例文件中的说明

**相关文件**:
- src/models/cluster.py
- src/config_loader.py
- src/steps/step_6_disk_mount.py

### 发现 #002

**日期**: 2026-02-25
**阶段**: phase-1
**类型**: 问题
**严重程度**: 低

**标题**: HostsParser导入路径错误

**描述**:
在config_loader.py中，HostsParser的导入路径使用了相对导入`.utils.hosts_parser`，但在某些执行环境下会失败。

**影响**:
- 批量节点解析功能无法正常工作
- 测试用例无法正确运行

**解决方案**:
将导入路径从`from .utils.hosts_parser import HostsParser`改为`from utils.hosts_parser import HostsParser`

**相关文件**:
- src/config_loader.py

### 发现 #003

**日期**: 2026-02-25
**阶段**: phase-1
**类型**: 经验
**严重程度**: 低

**标题**: merge_with_individual_nodes方法匹配逻辑

**描述**:
HostsParser的merge_with_individual_nodes方法通过hostname进行匹配，如果个别节点的hostname与批量节点不同，会被视为新增节点而非覆盖。

**影响**:
配置合并时需要注意hostname必须一致才能实现覆盖效果

**解决方案**:
更新测试用例以正确反映这一行为，在文档中说明匹配规则

**相关文件**:
- src/utils/hosts_parser.py
- tests/test_hosts_parser.py
